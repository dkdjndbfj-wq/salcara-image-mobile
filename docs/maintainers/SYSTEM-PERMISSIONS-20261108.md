# 系统权限与恢复交互（2026-11-08）

系统授权按功能触发，不在启动时集中索要权限。拒绝某项权限只阻止对应操作，不阻止文字聊天、查看任务或连接电脑。

| 功能 | 触发时机与访问范围 | 拒绝后的行为 |
| --- | --- | --- |
| 扫描配对码 | 用户进入扫码流程时申请相机 | 不挂载相机、不交换配对票据；永久拒绝时提供系统设置入口 |
| 拍照、拍摄头像 | 用户点拍照时申请相机 | 拒绝时不打开相机；普通拒绝可下次再申请，永久拒绝可去设置 |
| 选择图片、头像 | 直接使用 Android/iOS 系统照片选择器 | 不以整个相册读取权限作为前置条件；只取得选中图片；取消不添加附件 |
| 保存图片 | 确认本地文件可用后请求添加照片权限 | 拒绝或用户取消操作时不写入，也不报告保存成功 |
| 语音输入、Live 语音 | Android 请求录音权限；iOS 由原生录音组件请求 | 不授权不录音；永久拒绝可去设置；启动失败释放已建立的实时连接、播放器、监听与常亮状态 |
| 任务通知 | 首次发送任务或用户主动开启通知 | 分开显示用户开关与系统实际授权；拒绝时提供系统通知设置入口 |

`src/system-permissions.ts` 使用明确的权限错误类型和 iOS 原生麦克风错误码，不把网络错误或普通服务端的 permission denied 当成手机权限问题。多个并发麦克风操作共享同一次系统请求。设置恢复提示去重；点“去设置”才跳转，安卓系统返回可以关闭，跳转失败给出手动路径。

从系统设置返回后不会自动重试拍照、录音或保存。用户再次触发操作时重新检查权限，避免恢复授权后产生非预期操作。

Android 配置把媒体权限限定为照片，屏蔽 `READ_MEDIA_AUDIO`、`READ_MEDIA_VIDEO`、`SYSTEM_ALERT_WINDOW`；保留录音、相机和旧 Android 添加图片所需的存储权限。不要仅编辑生成的 manifest；配置入口是 `app.json`，构建后仍须核对最终 APK 的权限。

厂商自启动、电池优化和后台限制属于系统设置能力，不能假装成所有安卓手机都有的标准授权框。用户主动开启后台待命时沿用已有说明与系统设置入口。系统强行停止、手机重启、后台受限的边界见 [后台恢复说明](REMOTE-BACKGROUND-RECOVERY-20261107.md)。

## 验证与发布边界

- 权限与照片选择新增 11 项回归：显式设置跳转、系统返回、提示去重、跳转失败、并发麦克风申请、iOS 原生错误码、无需全库权限选图、拒绝相机不拍照和取消不添加附件。
- 首轮受影响的权限、相册保存、远程图片导出/查看、扫码和语音 8 套 / 90 项通过；后续资源释放与菜单变化按影响范围补跑，不将重复执行累计为测试数量。
- 实时语音补充了连接建立后拒绝录音的资源释放回归，语音文件 6 项通过；权限助手、扫码、通知菜单及安卓返回行为补跑 4 套 / 25 项通过。TypeScript 检查通过。
- 正常配置与测试配置均通过 Expo 插件解析检查。
- 自动化测试使用模拟系统授权结果。仍需用实际安装包在 Android/iOS 上验证首次允许、拒绝、永久拒绝、去设置后允许、权限撤回和选图器取消。当前没有连接真机，也没有完成 iOS 构建验收。
