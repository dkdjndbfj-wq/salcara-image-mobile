# 画布入口与完整交互规划（2026-11-05）

状态：用户确认按 Hermes Desktop 后，正文预览卡片 → 动态侧栏、同标签预览/源码、隐藏保活和图片查看器 → 图片画布已实施并验收；完整项目编译、设计版本管理等后续条目仍未完成。废止此前“顶栏常驻画布入口 → 两类画布目录”的设计。

## 目标与类型

保留界面预览与图片画布两种能力，入口随实际内容出现。普通用户不生成界面时，不增加界面设计菜单、空目录或顶栏按钮：

| 类型 | 用途 | 主要操作 |
| --- | --- | --- |
| 界面设计 | 可运行的网页、应用界面和交互原型 | 页面交互、预览/源码、设备尺寸、元素批注、继续修改、版本比较与恢复 |
| 图片 | 同一会话中的生成图及参考图 | 单图聚焦、全部图片、多选、缩放、区域批注、下载、继续改图 |

PDF、Office 和普通文本继续属于“对话产物”，不伪装成界面设计画布。图片形式的 UI 效果图仍归图片；真正可操作的 HTML/React 页面归界面设计。

官方资料核查确认图片查看器具有 Focused / Canvas、多选与批注；HTML 交互预览具有源码查看和批注修订。下述内容驱动的接线遵守用户明确的入口要求，不声称所有宿主的交互完全相同。

参考：[图片生成](https://learn.chatgpt.com/docs/image-generation)、[产物查看器](https://learn.chatgpt.com/docs/artifacts-viewer)。

## 入口与打开结果

| 来源 | 用户看见的入口 | 打开结果 |
| --- | --- | --- |
| 普通主对话 | 不显示常驻“画布”或“界面设计”入口 | 保持正常对话；没有成果就没有该成果入口 |
| 正文中的界面成果 | 可直接预览的框，带真实名称、状态及展开操作 | 点击预览框的展开区域，打开右侧对应成果标签，不经过画布目录 |
| 正文中的图片 | 点击图片 | 先进入完整单图查看器，保留缩放、下载与分享 |
| 单图查看器 | “图片画布”或明确的 Canvas 视图切换 | 进入当前会话的多图画布；返回时回到此前聚焦的图片 |
| 已打开的界面成果 | 右侧现有标签及正文原卡片 | 同一成果复用已有标签，不再开重复页面 |
| PDF、Office、普通文件 | 正文文件卡片或既有文件工具 | 对应文件查看器，不先进入画布目录 |
| 新建但尚无会话身份 | 无常驻画布入口 | 先正常对话；真实成果返回后才出现对应预览框或图片 |

实施时移除主对话中 `outputs.button` 的常驻展示，不替换成另一个常驻画布按钮。Hub 平板/手机和 Direct 使用相同的正文入口。动态成果标签不加入 `WORKSPACE_PAGES` 常驻工具目录，也不改变初始标签页。

正文预览框使用中性色，显示名称、小预览及必要状态。只有可运行的明确成果才按界面预览呈现，普通 HTML/JSX 代码片段仍按代码显示。预览内按钮和输入框用于实际交互，独立的展开操作负责进入侧栏，不能让每次点击按钮都展开面板。

## 平板与手机布局

界面设计作为现有右侧工具栏中的动态成果标签，复用同一套标签、隐藏/恢复及全页逻辑，不再创建独立“画布中心”或第四列。图片画布属于图片查看器的视图，保持独立路径。

宽平板的界面预览：

```text
会话导航 | 主对话                          | 右侧现有标签栏
         | 界面成果预览框 → 点击展开       | 成果名称  ×
         | 原会话消息和输入框              | 预览 / 源码 · 尺寸 · 版本
         |                                 | 实际页面与批注
```

- 由既有 `TabletThreadFrame` 按实际可用宽度处理分屏与左栏折叠；界面预览使用右侧一列，可用既有全页操作，不另外发明布局断点。
- 窄平板、分屏窗口及手机复用工具区全页覆盖，“返回聊天”始终可见。添加批注后回原草稿，由用户发送。
- 隐藏侧栏保留预览表单、滚动、源码草稿和运行实例；关闭具体成果标签才释放预览实例。未保存检查仍适用。两个操作都不能顺便关闭其他工具或结束 Agent。
- 主对话仍使用原有消息、草稿、引用、附件、队列和发送状态，不创建“设计专用”会话或额外输入框。
- 界面尺寸只改变预览视口，不改变手机/平板的实际应用布局。React 项目 CSS 与交互在对应尺寸里实际运行，不能用缩放截图代替。
- 预览的文字输入和键盘快捷键优先属于预览；画布返回、编辑器快捷键不截获用户在网页里的正常输入。

## 用户主动操作与 Agent 生成

| 事件 | 页面行为 | 状态保留 |
| --- | --- | --- |
| 用户点击正文界面成果的展开操作 | 选中并展开侧栏中的对应成果 | 记录原消息及版本，保留主对话位置与草稿 |
| Agent 生成新界面 | 正文出现预览框；需要登记的侧栏页只后台登记 | 不展开侧栏、不切换当前标签、不抢键盘焦点 |
| Agent 生成图片 | 正文出现图片 | 不自动进入单图查看器或图片画布 |
| Agent 修改当前正在看的成果 | 原卡片/标签提示“有新版本”，用户决定是否查看 | 不覆盖正在编辑的源码、批注或控件状态 |
| 用户从图片查看器进入图片画布再返回 | 回此前聚焦的原图片 | 保留图片缩放/位置与画布批注 |
| 用户隐藏界面预览或关闭图片查看器 | 回原聊天消息位置 | 不强制经过目录，不清主草稿 |
| 系统返回、Escape、返回按钮 | 遵循相同层级和未保存检查 | 不出现按钮可退、系统返回无声失效的两套规则 |
| 仅关闭画布 | 关闭查看面 | 不停止 Agent 或远程开发服务器；停止任务仍走明确的停止操作 |

用户在正常对话中提出设计需求及目标尺寸，使用既有发送操作。Agent 返回真实成果后出现预览框。展开预览不自动发送、创建新任务或修改项目文件。

## 持续修改、保存与版本

界面设计需要完成以下闭环，不能只验收展示一张页面：

1. 提出需求 → Agent 生成 → 正文成果卡片 → 打开实际界面。
2. 点击/输入验证交互，切换尺寸检查布局；查看源码和实际运行错误。
3. 选择界面元素或区域，添加修改要求；回填原对话，带成果、版本、元素定位与必要上下文。
4. 用户确认发送 → Agent 修改 → 原成果显示新版本提示 → 用户切换并验证。
5. 版本列表可查看、比较和恢复；恢复生成新的当前版本，保留原历史，不默默覆盖磁盘文件。

只读预览不用弹未保存确认。源码或批注已修改时，关闭、换成果、换版本、切换电脑/API/项目/会话均经过同一检查：保存后离开、保留本机草稿并离开、继续编辑。保存失败停留并保留内容；没有写权限时不显示可成功保存的假按钮。

用户编辑文件使用真实 revision 比较保存。Agent 新版本和未保存本机草稿分别保存，提供对比/选择，不默认合并。旧版本的元素定位不能直接套用到新版；提示重新选择，保留原修改意见。

图片继续支持单图与多图批注、区域坐标、原图下载。改图要求绑定选中的原图和版本；缺少原图时明确提示读取，不能只发送一段没有图片上下文的文字并称改图请求成功。

## 来源、运行方式与异常状态

- 所有内容绑定电脑/绑定、Agent、API、项目、Code/Work、会话、成果 ID 和版本。目录、选择、批注、源码草稿与运行状态均按这个来源隔离；来源切换后的旧回调失效。
- 自包含 HTML/CSS/JS 使用现有隔离预览基础。React/JSX/TSX 需要明确的编译、依赖与项目运行支持，不能更改后缀或依靠手机浏览器临时 CDN 冒充支持。
- 项目预览在绑定电脑运行，经当前授权的远程预览链路传输。电脑的 localhost 不能直接作为手机可访问地址。新能力需要明确协议及 Bridge/Hub/Direct 接线，旧电脑清楚提示更新。
- 预览与主任务遵循同一权限和批准流程。页面脚本不能拿到应用凭据；不能因为打开画布就扩大可访问的电脑目录或自动启动不明命令。
- 图片能生成 UI 效果图，不意味着能运行界面；原生 iOS/Android 项目未接模拟器或设备时，不把网页预览称作原生运行。
- 空目录、生成中、编译中、可用、更新中、失败、断线、只读、缺少能力均有独立状态。失败保留上次成功预览及日志，清楚标注旧版；不把失败版本替换成空白页。
- 重连重新核对成果和版本，恢复本机草稿，不自动重发生成/修改请求。刷新应用后恢复可解析的成果标签，运行中的服务需要重新查询真实状态。不能恢复的纯内存产物明确提示从原消息重开，不伪造空标签。
