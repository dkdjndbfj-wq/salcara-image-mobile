# 远程对话能力核对与本轮修复（2026-10-11）

这是一份维护者审查清单，不是“已完整复刻 Codex”的宣传。范围是手机编程对话、Bridge 对话适配、Hub 透传；不更改其它产品界面，不发布、提交或部署。现有用户/Claude 修改保留。

后续已继续实施普通图片草稿、新任务持久回执/精确 ACK、共享凭据预算、进程退役与跨任务消息一致性。本表按实际能力更新；下方较早“最终验证”是对应阶段的历史候选，最新统一手机 1515/1523 项通过及 Bridge/Hub 验证以 [远程内核可靠性记录](../../../salcara-desktop/remote/bridge/docs/REMOTE-KERNEL-RELIABILITY-20261011.md) 为准，不累加各阶段数字。

## 调查基线

先使用 OpenAI Docs 查阅官方能力，再检查本地实现与生成的协议。官方 Remote 公开介绍涉及队列、引导当前任务、旁路问答、审批、审查等交互；这些用于建立核对目录，不能据此假定第三方软件能调用桌面应用的同一入口。[官方 Remote 介绍](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)

本地 Codex 适配器的依据是 [App Server 文档](https://learn.chatgpt.com/docs/app-server) 和现有生成的协议类型。App Server 与官方桌面插件的已授权接口是两条不同执行面；公开 RPC 的存在不等于拥有原桌面进程的连接。

Claude Desktop 需要单独看待：本项目支持的是用户明确选择后的第三方/API 配置（由桌面端保存、备份、切换和恢复），不是把 Claude Desktop 原生聊天进程当成反代控制端点。手机可在 API 目录中选择这条来源；只有 Bridge 自己拥有并确认的 Claude Code worker 才能执行同会话发送/停止/继续，Claude Desktop 原生历史没有该控制能力时仍保持只读。

ChatGPT 可以在其产品内协调任务，但本项目没有因此获得 ChatGPT 账号、另一项任务或云会话的访问授权。[官方 Voice 任务协调说明](https://learn.chatgpt.com/docs/features/voice?translationFallback=zh-Hans) 长期目标也需要单独的生命周期，不等同于无限自动重试一条消息。[官方长期任务说明](https://learn.chatgpt.com/docs/long-running-work?translationFallback=zh-Hans)

`codexDelegation` 是当前原生读取适配器已经处理的扩展，不在已检查的公开 `UserInput` 类型中。保留其观察到的类别，但不捏造它的来源任务或 ChatGPT 身份。

“另一项任务发送”需区分三件事：已有 companion 的控制任务向明确授权目标转发，是本地桌面桥接；手机保留目标收到的委派类别，是读取与显示；让任意外部 ChatGPT 云账号主动访问这些任务，则需要另一个正式授权入口。前两项不能作为第三项已完成的证明。配套的协议/companion 集成核对见 [对话输出复核记录](CODEX-CONVERSATION-AUDIT-20261011.md)。

## 本轮实际修改

1. Bridge：新增可选 `messageOrigin:{kind:"delegation"}`、`agentNickname`、`agentRole`、`forkedFromSessionKey`。只保留已观察元数据，不扩展权限。原生终止错误不再丢弃；同步拒绝及完成早于回包的状态竞态有回归测试。
2. 手机：消息投影、历史合并、缓存及 UI 保留委派类别；同文委派不能确认或删除手机的乐观消息。未知额外来源字段被丢弃。
3. 侧边栏：使用真实 nickname/role 和官方图标；按当前 sticky 执行面选目录；原生 list/read 分开核对，授权过期有本地时钟和点击时复核；必须在精确 session lease 内才能点选，不退回 CLI。主任务返回也经过这一入口；未知子任务显示“状态未知”，不假造刚更新或完成。只读 Claude Desktop 按当前账号 identity 与 Chat/Cowork scope 使用独立目录。新对话真实打开编辑器，不发送、不重启、不终止旧任务。
4. 队列：不再拼接不同提交或静默截图片；逐项持久化与原回执恢复；拒绝/缺图可手工处理，不循环自动重发。详细审查见 [队列专项记录](MOBILE-QUEUE-RELIABILITY-20261011.md)。
5. Bridge 队列预算：将新增元数据及附件描述计入保留/上传权重，防止扩展 DTO 后低估缓存负载。Hub 的 raw JSON 透传增加合成回归，验证新字段与会话游标不丢失。
6. 错误：CLI/原生/RPC 统一保留 Codex 已知 typed 条件；unknown item 仅生成有界中性占位，不泄露原始参数或结果；未知 turn 状态不当作 completed。原生不能换模型/凭据时，错误引导到既有电脑操作入口，不展示手机可实际覆盖的假操作。
7. 历史增量：修复 watcher 仅按数组位置去重导致同一条消息后续文字、phase、工具结果和终态丢失的问题。使用有界内容指纹与稳定 item/turn ID；越过可核验窗口时走真实 snapshot 恢复，不无限读取全部历史。具体实现与验证见 [Bridge 修复记录](../../../salcara-desktop/remote/bridge/docs/REMOTE-CONVERSATION-METADATA-20261011.md)。
8. 发送回执：新队列在原子回执选择处拒绝旧操作，不能用同文确认提交身份。失败接管以精确 requestId 和本次创建归属为准；SQLite 提交成功后才发布内存。电脑已确认执行但本地清理失败，保留原回执，不假称任务未发。数据库读取失败、损坏/重复回执不作为空列表覆盖；迟到磁盘读取不能覆盖刚提交的新回执。同工作区协调任务已整合普通新提交默认拒绝旧回执、明确原 ID 重试、原图片/模型/API 冻结及新草稿保留；本任务已用最终手机全量复验，不混用两组的编辑归属。
9. 未知线程状态：CLI 不再默认当作闲置并恢复/发送/重启；保留真实 busy/turnId，实际已运行任务仍可停止。已知 idle/notLoaded 可恢复。Native 切站判定本来已核对明确 idle；native 显示层的旧兼容回落未在本轮扩大改动，不能拿显示状态当控制授权。
