# 远程持久恢复与图片清理（2026-11-07）

本轮实现手机、Hub、Bridge 三端恢复通路，承接用户关于断线、后台、进程终止、服务器 SSD 和图片清理的要求。本文记录本地源码状态；没有部署服务器、替换正在运行的 Bridge 或安装手机应用。

## 已接通的恢复路径

| 场景 | 实际行为 |
| --- | --- |
| 发出前手机退出 | 发送前先保存待确认记录；本地保存失败不会继续派发。后台时立即提交当前草稿，不等待输入防抖 |
| 电脑执行后 HTTP 回执丢失 | 保留同一操作身份，查询原回执；不会生成新编号自动再次执行 |
| Hub/Bridge 普通重启 | Hub SQLite 保存结果、事件和图片；Bridge 保存执行占用、结果和冻结事件批次。重启沿用原身份和批次 |
| 电脑已经离线 | 手机仍可读取 Hub 尚在保留期内的事件；需要补全缺口时再从电脑原 Agent 历史恢复 |
| 手机读到内容但写盘失败 | 不推进持久游标，不向服务器确认收取；保留服务器副本 |
| Bridge 执行中退出且无法确认结果 | 保留 uncertain，按原操作核对；不会把未知结果当作未执行重放 |
| TTL 到期或正文截断 | 保留明确过期/缺口状态；有电脑历史时补读，不能显示为完整恢复 |
| 换绑或切换来源 | 队列、回执、图片按来源隔离；旧回包不得覆盖新连接。Bot 增加服务端绑定代次，普通重启稳定、换绑失效 |

手机 `durable-commands.ts` 将本地意图 UUID 和服务端执行 UUID 分开保存。`prepare` 只签票据；票据映射写入手机后才允许执行，来源授权对最终命令获取。恢复先查询原操作；已完成结果写入手机后才 ACK。旧 v1 待确认记录不升级成新 UUID，已经使用 v2 的操作也不因能力暂时消失而降级。

手机 `durable-events.ts` 保留原始事件，包括当前客户端尚不理解的事件，按累计内容合并重复片段。页写入成功后才 ACK，游标与存储世代一起保存。新世代保留已显示内容、清除旧序号戳并从 0 补读；冷启动不会重新激活过期审批。

Hub 离线执行开关默认关闭。启用后仅接受开放来源策略下的 `session.start/send`，执行期限固定为首次 prepare 起 10 分钟；过期不续签。审批、停止、steer/continue 和 Git 写操作不进入该队列。正文保留 7 天不意味着指令可在 7 天内任意执行。

## 保存期限与容量

| 层 | 默认预算与清理 |
| --- | --- |
| Hub 正文/结果 | 未确认 7 天，可设 1–30 天；确认后最多 24 小时；单结果/累计轮次正文 2 MiB，超限保留缺口与终态 |
| Hub 原图/分片 | 分片无进展 1 小时；原图最后一个真实引用到期后再留 24 小时；清理时保护活动读取 |
| Hub 缩略图 | 7 天 LRU，每绑定 32 MiB、全站 min(128 MiB, 总额度 5%)，计入总预算 |
| Hub 总空间 | min(5 GiB, 卷容量 10%)，每绑定 256 MiB；至少预留 max(2 GiB, 卷容量 5%)，满额拒绝新大内容 |
| Bridge | 图片跨绑定合计 256 MiB/1024 文件，分片 48 MiB/8 个上传；普通图片 24 小时、分片 1 小时；待上传/读取中的图片受保护 |
| 手机图片 | 可重建缓存 64 MiB/7 天；部分文件 1 小时。单轮最多 500 文件/50 MiB，优先删派生图 |
| 手机事件 | 每会话 2 MiB、合计 32 MiB/128 会话，7 天；写满时停止 ACK，不能静默丢弃服务器未确认内容 |
| 手机操作 | 4096 个身份记录；结果每项 2 MiB、合计 16 MiB、7 天；清理正文仍留防重身份，满额拒绝新操作 |

Hub 复用服务内清理器；手机启动及前台每 5 分钟维护，后台停定时器；Bridge 每分钟清理。这里只清应用管理的缓存，不删除项目文件、原 Agent 历史、用户图库或另存成果。服务器容量、保留天数及离线队列可在管理员“系统 → 消息与图片存储”设置。

容量不足先回收已过期、无引用缓存；仍不足则保留原草稿并拒绝新内容，不靠删除待确认图片腾空间。当前开发机磁盘余量低于 Hub 默认 5% 预留，真实准入会被拒绝；相关测试使用受控磁盘容量夹具，没有删除用户文件或降低正式默认值。

## 图片显示与传输

新 Hub 的 `attachment.read variant=thumbnail` 已贯通手机列表：先取独立缩略图，点击后按需下载原图，原图引用不被缩略图 URI 覆盖。旧 Hub/Direct 保持兼容读取路径，不能称为所有通路均已避免原图下载。

- 单张传输原图最大 8 MiB，每次输入最多 4 张；分片逐块处理，不同时保存完整 Base64 分片数组。
- 手机从 JPEG/PNG/WebP 真实头部检查尺寸，256 KiB 有界读取，普通处理不超过 16 MP；拒绝动画或不能可靠判定的头部。
- 列表长边 512，预览长边 1600 且最多 4 MP；同图合并请求、单个预处理队列。
- 受管可见图片源预算 32 MiB，收到内存警告后 16 MiB；离屏、关闭预览或后台释放源和可见租约。
- 原图由草稿、待发消息、画布引用保护；派生图可过期重建。显式 URI 与正在显示的租约保护被使用的派生文件。
- 网页使用独立 Blob 缓存；原生使用受管文件，不调用网页不支持的原生文件系统接口。

这些是像素源和缓存预算，不是进程 RSS 硬上限。原生图片库仍可能短暂解码源图，需要真机峰值验证；没有实现任意超大图的分块缩放。Hub 单缩略图 worker 输出 JPEG 512，16-bit PNG 可保存原图但拒绝生成缩略图。

## 提示、后台与通知

沿用已完成的生命周期门禁：普通网络异常 8 秒后轻量同步状态、持续 30 秒才展开提示；后台停止计时，回前台重新给窗口。明确权限拒绝、本地保存失败和已可能执行的待确认状态不被统一延迟掩盖。缺尾回复需相同内容稳定至少 60 秒、三次成功快照才判残缺，网络失败不算成功快照。

Hub 推送任务已持久保存，最多重试 1 小时、按通知 ID 去重；推送失败不重发业务指令。Android 普通后台需权限和系统允许，iOS 需 FCM/APNs 配置。Android 强制停止、厂商省电及系统杀进程下不能保证实时通知；重新打开后的恢复依靠已落盘记录。Direct 没有服务器后台推送通路，冷启动仍需连接原电脑。

## 隔离与运行边界

Bridge 注册和 SSE hello/heartbeat 接收 `eventScope/eventScopeRequired`，冻结事件批次、图片目录/请求和执行回执使用同一代次。持久队列的代次不能单独充当握手授权；重启先恢复图片保护，认证完成才补传。不同代次会清除旧私有队列与会话缺口元数据，只保留不含会话内容的全局恢复标记。锁内复核身份，避免旧注册回执覆盖新绑定。

仍有带 scope 的未同步队列或具体会话恢复记录时，跨站迁移缺少目标图片迁移事务，必须明确拒绝并保留原队列，不能假称搬运成功。先恢复原站同步，再切换。普通空队列切换继续支持；仅有无会话身份的全局缺口标记不会永久阻止切换。

Hub 事件、正文和图片内容加密；Bridge 事件和回执加密，但供 Agent 按路径读取的图片目前是私有目录中的明文文件。均不能称为端到端加密。SQLite 是单写实例，不能由多个 Hub 共享同一文件。恢复旧备份需显式更新存储世代，不能自动识别所有外部磁盘回滚。Docker 日志目前为 10 MiB×3 容量轮转，不是按 7 天删除。
