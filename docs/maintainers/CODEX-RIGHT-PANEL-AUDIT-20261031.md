## 必须保留的本项目规则

这些来自用户明确要求，不假称官方文档已确认完全相同：

1. 首页确定电脑、Agent 和 Code/Work；会话输入框及内部目录不得任意转换 Code/Work。计划是独立选项。
2. 用户打开网页：显示右栏并激活目标页；Agent 在电脑打开网页：手机同步标签，但不展开面板、不抢焦点。
3. 两个不同 `pageId` 即使 URL 相同，也不能合并；同一页面后续导航更新已有标签。URL 仅用于缺少稳定页面身份时的兜底。
4. 切换电脑、绑定身份、Agent 或会话不能串用 API、文件、草稿、标签、终端或网页控制。
5. 关闭面板、切换标签、关闭标签、终止任务是不同动作；不能通过关闭查看页静默取消主任务。
6. 真实连接和演示应复用页面与交互规则，只替换数据/传输。模拟状态必须明确标识。

## 重构顺序与验收基准

以下是建议实施方案，不是已完成声明。先重构共享面板容器和状态，再接各类内容，避免分别修补两套页面。

1. **统一容器**：一个共享的标签模型/标签栏/新增入口/布局状态；所有标签可关闭；支持隐藏、分屏、全页。暂不把当前固定五标签当默认标准，空态及默认页要明确设定为产品选择。
2. **纠正侧聊**：把临时侧聊与已存在的持久化侧问历史分开。旧记录保留；不得自动删除或迁移成临时记录。宿主没有临时侧聊协议时显示明确能力边界，不用持久化侧问暗中替代。
3. **统一审查**：真实 Git 状态与轮次变更应在同一审查语义中分 scope；文件 diff、正文变更卡片和 Git 管理不再成为三套互相矛盾的状态。Git 操作必须针对正在预览的版本。
4. **浏览器与文件**：保持一个页面/文件一个标签、来源/焦点规则、重名路径辨认、草稿保护。补浏览器批注等前，先明确远程画面流、原生 WebView 与真实浏览器共享会话的技术区别。
5. **子智能体和执行详情**：先核实桌面实际入口和详情样式，再确定标签；扩展控制可保留为本项目能力，但不能以“Codex 原样”描述。
6. **验证**：同一套脚本分别走演示、Hub、Direct；覆盖右栏关闭时 Agent 新页、用户主动新页、关闭/恢复标签、全页返回聊天、电脑切换、离线恢复、无能力空态、未保存文件、临时侧聊生命周期。

未查明：当前版本加号的全部项目/排序、默认空页、标签拖动/分离规则、侧聊关闭单个标签与退出应用的精确差别、Agent 详情是否固定留在右侧。以上不得靠现有实现倒推。
