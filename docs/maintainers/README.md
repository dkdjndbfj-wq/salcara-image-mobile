## 2026-10-06 最终内核复核

- 重复扫码回调按同一二维码票据合并为一个 claim；不同二维码会使旧尝试失效，旧结果不能选中旧电脑。
- A→B 切站的非敏感交接日志会在进程启动、手机回到前台和重新打开远程页时尝试恢复；恢复请求带连接代际和当前 Hub 身份保护，退出登录或重新配对不会被旧恢复结果覆盖。
- 启动连接选择写入增加代际保护：扫码、切站或旧请求在设置写入期间失效时，会在同一串行队列内恢复原选择；显式退出、解绑、凭证失效会清理未完成的切站日志，避免下次启动误恢复旧目标。
- 未改手机 UI、文案、样式或动效。
- 验证（最终回归）：`npm run typecheck`；Jest 71 suites、946 tests passed，8 skipped（共 954 tests），约 99 秒。历史读取、会话和实时同步定向回归 115 tests passed；此前的 941 为中间阶段数字。

## 2026-10-06 远程边界复核（本轮）

- 可见会话的长轮询和原生 Codex 桌面读取现在都接受同一个 `AbortSignal`。离开会话、切后台或切换会话会取消 `/app/events`、只读命令和重试等待；取消不会增加退避次数，也不会把旧结果写回新会话。
- 手机端的切站恢复、主动 A→B 切站和解除绑定进入同一串行门；恢复不会与用户操作并发改写当前 Hub。解除绑定还占用同一设备级 API 变更锁，避免 API 切换在解绑中途落到旧站点。
- 解绑后的本地索引清理即使遇到 OS keychain 删除异常也不会重新激活已撤销的档案；索引已落盘时继续清理其他站点，索引写入失败则保留记录供重试。
- 新增回归：只读桌面命令收到取消信号时传输立即终止且不重试；原有 live-sync 离开页面取消 held read 测试继续通过。
- 修正扫码页返回后台再回前台时相机自动扫描不会恢复的生命周期边界；修正流重连退避在已取消信号下仍等待整段退避的问题。
- 修正历史分页取消后仍卡在 `loadingEarlier`：取消只清理同 Hub、分页 revision、历史 revision 下仍属于该请求的 loading，保留内容与游标，不能清掉新分页的 loading。
- `ThreadView` 的初次历史读取和分页读取显式监听 AppState；初次即后台不读，切后台立即取消，未完成初次读取回前台重试。取消返回不再误标为“已取得新 snapshot”，草稿与任务不会被重置或重发。四个生命周期故障已先复现失败再修复，另有旧取消结果不得清理新请求的回归。
- 未改手机 UI、文案、样式或动效。

集中核对记录在工作区 `docs/REMOTE-REPAIR-AUDIT-20261006.md`，含从本轮修复开始的十项用户问题、代码索引、测试结果与真机验收清单。本次续接仅改请求生命周期；此前直接扫码要求改了绑定导航，不能把整轮表述为“从未修改前端文件”。没有构建新 APK、发布或部署。

## 2026-10-05 内核复核

A/B 中转站切换的手机内核已补齐不同站点设备 ID、持久化回执丢失、离线恢复和连接代际竞态：只有同一 `computerId` 才会请求电脑先切站，待确认消息/问题回答会阻止切换，旧异步结果不会覆盖新连接。API 选择若由电脑明确返回唯一的已配对同源站点，会自动走“API + Hub”原子交接；不同源仍保持解耦，不猜测站点。手机在 B 上必须核对 `operationId`、payload hash、Hub 和 deviceId，不能只凭在线状态恢复。手机仍只发送不透明 API handle，密钥、站点设备密钥和服务器地址凭证不出电脑密钥库；未改手机 UI、文案或动效。该阶段记录的 934 是中间值，当前结果以 2026-10-06 章节为准。

## 2026-10-05 跨站设备 ID 与并发补丁

- 同一台电脑在 A、B Hub 上可能拥有不同 `deviceId`。手机执行 API + Hub 原子切换后，所有状态读取改用 B 的设备 ID；原会话 key、电脑保存的会话目录和 API 密钥不变。
- 桌面端切站期间暂停新的事件上传批次；已有 in-flight 上传会阻止切换，探测阶段产生的新事件会让最终检查失败并保留 A，避免跨站错发或丢失事件。
- 新增跨站测试覆盖：A=`pc-a`、B=`pc-b` 时，API 选择完成后不会用 A 的 ID 请求 B。

## 跨域 API 与 Hub

同源且唯一的 API/Hub 站点仍可由电脑返回公开站点元数据，手机直接走原子切换。API 域名和 Hub 域名不同，或同一域名对应多个已配对站点时，不根据域名猜测归属：手机先切换已配对的目标站点，再选择 API。这样不会把 B 的 API 误套到 A 的电脑链路上，也不会把某个 API 账号的密钥、地址或设备凭证发到另一站点。
