# Codex 对话与输出复核（2026-10-11）

本轮以本机 `codex-cli 0.145.0` 的 `codex app-server generate-ts --experimental` 类型和 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 核查原生会话、回合、条目和通知；对照实际 Bridge、Hub、desktop-companion 与手机端代码。生成类型代表本机协议版本，不代表所有 Codex 云端和桌面产品能力已在 Salcara 实现。

## 本轮补齐

- **跨任务消息边界**：原生 companion 的控制任务与目标任务分离，目标使用显式授权的原始线程 ID。controller 不能成为目标；发送操作的回执绑定目标和正文，不把消息不明状态重发成新操作，不自动改用 CLI。手机缓存、草稿、排队和发送仍受站点、配对身份、设备、会话及执行端约束。
- **发送确认身份**：Codex CLI 续聊把发送操作 ID 放入 `clientUserMessageId`，原生 `userMessage.clientId` 透传到手机。有真实 clientId 时严格匹配自己的待确认消息；其他 clientId、子消息和明确委派消息不能吞掉同文本的手机输入。旧协议没有该字段时保留兼容行为，不能由文字猜出发送任务。
- **原生回显兼容**：真实 Desktop `read_thread` 不返回 clientId，且手机自己的转发也可能带委派类别。成功回执只移除本次精确 localId；不确定回执不重发，旧 owner 结果不清理新连接。只有已有待确认回执才能复用乐观行，新发送的相同文本及同毫秒输入仍保持独立，并由各自 CLI clientId 确认。
- **容量错误**：保留 Codex `serverOverloaded` 等明确执行条件，使用 `model_capacity` 错误码贯通 Bridge reply、Hub 回执、时间线及手机。上游 HTTP/SSE 错误只读取有界已知字段，容量错误使用固定安全消息；不透传服务商原始错误正文。手机显示换模型/稍后重试，保留原消息和失败状态，运行时正在重试的 notice 不被当作最终失败。
- **最终回答与过程说明**：真实 `agentMessage.phase` 保留为 `commentary` 或 `final_answer`；未知 phase 保持旧协议兼容。过程说明不充当最终回答，不接收最终回答的耗时/用量。仅过程说明、工具或空回复的成功回合仍显示完成边界。
- **回合顺序**：同一 turnId 分别保存开始与终态边界，终态使用完成时的排序位置；不会跑到用户消息前。旧缓存中合并的边界在恢复/合并时升级，失败/中断不会把时长统计带到下一回合。
- **动态/MCP 输出**：动态工具的 `contentItems` 文本、命名空间和失败输出保留；MCP 无文本内容时保留 `structuredContent`，不展示 `_meta`。图片仅通过私有 `ImageData` 交给有界、magic 校验、会话绑定的附件导入器；远程图片 URL、音频 URL 不会被自动读取。音频目前只保留标记。
- **原生条目与通知**：补齐 hookPrompt、sleep、计划 delta、MCP progress、原生名称变化、模型 reroute、明确线程的 warning/guardianWarning，以及旧版 compact 通知。全局警告不伪分配给某个任务；通知有稳定 ID 时按 ID 更新，防止钩子 start/completed 重复。
- **宿主更新**：companion 0.4.2 增加本机 Codex 26.1007.2314.0 明确版本校验，实际 archive 验证通过。真实投影缺少的 clientId、动态工具结果和 typed error 不假装完整；宿主环境、实际 provider 与 Android 链路仍需验收。
- **计划权威终态**：流式计划是草稿，不能假定拼接后的文本等于最终计划。完成态的 `outputFinal` 即使正文为空也能清除旧草稿；无正文的重复终态仍保留图片附件与子会话句柄。
- **图片输出**：保留 `image_view` / `image_generation` 分类、对应图标、附件和统计；重复终端事件不会擦掉已收到的输出附件或子会话导航。
- **历史增量与状态**：轮询比较条目内容、phase 和回合状态摘要，同一条目追加的文字及最终回答不会因位置已读而漏掉。缺失或未知回合状态不伪造完成；只按明确的原生终态生成边界。Bridge 在锁内复制历史附件引用，避免图片回显与历史读取并发访问共享表。
- **图片排队存储**：按配对范围保存私有图片快照、摘要及文件所有权；恢复只加载元数据，轮到发送时再读取并核对实际字节。图片丢失或被替换会阻断该行，不能降级为纯文字发送。解绑先保存撤销围栏，再删除明确归属的普通文件；不递归删除目录。收据/历史仍可能引用的图片保留到明确解绑，受大小预算限制。
- **独立提交与回执**：普通发送、历史重发及新排队提交均不能复用旧的同文回执；只有明确携带原 `retryRequestId` 的重试可以续用，串行提交前再次核对原 ID，已清理或变化的回执不能变成新任务。失败返回回执 ID 及本次是否创建，阻断旧回执时不能把新行标成尝试过。菜单的原消息重试和自动恢复保留原 API、模型与执行端，新文字和图片仍保留在输入框。
- **未完成上传的图片恢复**：收据保存原图片摘要，恢复只读取原来源并核对摘要，不接受用其他图片替换旧附件 ID。已经上传的图片直接复用原附件 ID，无需本地文件仍存在；无摘要的旧未完成上传记录保留并要求核对，不能自动改发。
- **回执存储失败**：SQLite 读取失败、损坏/未知 JSON、非法或重复记录均拒绝新提交；只有实际空值代表无记录。成功写入后才发布内存状态，迟到的磁盘读不能覆盖新回执；已确认发送但本地清理失败也不制造新 UUID。
- **永久撤销的回执退役**：主动解绑和带配对凭证的 devices 请求确认 401/403 后，先持久化确切旧凭证 scope 的退役围栏，再清理该范围的发送和问答回执，释放旧记录占用的容量。多站点部分失败、新 QR 替换和迟到的上传/写入也不能保留或恢复已确认撤销的范围；新凭证、其他有效配对和无法确认归属的记录仍保留。存储失败保留可重试的连接索引，不能制造新的发送。匿名 `/ping` 的 401/403、本地退出和暂时断网不证明配对失效，不触发永久退役。

## 功能矩阵与明确缺口

| 对话能力 | 当前状态 | 边界 |
| --- | --- | --- |
| 原生任务列表、分页、置顶/最近、项目与子会话导航 | 已实现 | 只列有权限的真实句柄，不按标题认任务 |
| 历史正文、推理摘要、工具、文件 diff、计划、审查和压缩条目 | 已实现 | 有界分页/输出；不推断未返回的内部内容 |
| 图片输入和工具图片输出 | CLI 已实现 | native surface 未声明 attachments 时关闭输入；任意文档和音频未实现 |
| 另一任务发送消息 | companion 已实现 | 显式授权/租约/幂等；原生实际桌面链路仍需验收 |
| 接收消息的 clientId、委派类别 | 部分 | clientId 是确认字段，不是可信发送任务 ID；仅保留实际返回的结构化分类，不从 wrapper 或“ChatGPT”文字推断来源 |
| 执行中排队、多条消息、恢复与失败处理 | 已实现 | 按消息保留顺序与发送选项；不明发送不能自动重发成新命令 |
| 中途 steer、`/side`、完整任务 fork/archive/delete/云端 handoff | 未实现完整远程控制 | 当前 queue 不等于 steer，手机本地改名不等于原生 rename 控制 |
| 容量/限流/额度/密钥/模型接口错误区分 | 已实现 | 容量不是密钥失效；HTTP 429 本身不能证明模型满载 |
| 停止、审批、用户问题 | 能力驱动实现 | 原生 companion 停止能力未开放；审批只来自已安装并显式启用的真实同步 hook |
| Goals、语音实时会话、云环境与工件管理 | 未实现完整产品链路 | 不能将本机 app-server 类型或普通 SSE 视为这些功能的验收 |
| OAuth、受限来源、反代保险 | 见 Bridge Cockpit 矩阵 | 本进程租约及旧入口封锁已实现；真实来源证明/账号/发行包真机仍需验收 |

## 验证规则

回归包含：容量失败分类及 UI、不同客户端同文本输入、真实 clientId 确认、commentary-only 回合、开始/终态排序、旧缓存升级、钩子去重、空计划终态、动态/MCP 输出及私有图片、客户端权限与别名、反代独立启动拒绝、历史内容更新、图片附件并发快照、图片文件所有权与配对撤销、独立排队提交和回执归属；撤销回执还覆盖多站点部分失败、旧 revoke/refresh 与新 QR 竞态、匿名 discovery 鉴权失败、迟到的准备/执行/磁盘写入及本地清理失败后的重试。

本轮测试只使用 synthetic fixture，不读取真实账号文件、配对 Key 或付费推理。最终全量结果以本轮交付记录为准；代码和合成测试通过不能代替实际 Codex Desktop、Hub 与 Android 真机链路验收。

问答 UI 回归的 UUID fixture 已按每个新操作生成独立值，重试仍匹配原持久回执。快速重复提交和切换会话用例同时检查发送次数、目标、回答选项以及两个新操作的不同 ID；不以放宽重复记录校验消除测试冲突。

撤销生命周期合并后的稳定验收：TypeScript 检查通过；Jest 82 套通过、8 套跳过，1157 项通过、8 项跳过，118.542 秒。289 个源文件测试前后摘要均为 `f62c8b88ac2cd528ae8dc8a88c769f454f2002d13d4fb5caa1dfffa31f469ce3`，清单无差异，`git diff --check` 通过。随后原任务新增的文件查看与正文链接功能另行验证，不计入本阶段全量结果。
