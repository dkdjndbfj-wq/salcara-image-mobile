# Remote skill display metadata

`SkillReference` keeps `name` and optional exact `path` as execution identity. Optional `displayName`, `brandColor`, and `iconSmall` are display snapshots. They are copied through explicit picker selection, composer mentions, queued drafts, delivery receipts, user messages, and local history caches. Literal `$name`, `/name`, and `@name` text never gains invocation authority. Catalog keys still include the selected agent/source/account/project scope; appearance changes affect the existing catalog revision.

The Codex Bridge reads interface metadata only from enabled native catalog entries. It resolves an icon relative to that skill's directory (or accepts an absolute path inside the same resolved directory), rejects escapes and nonregular or oversized files, decodes PNG only, and reencodes a static raster no larger than 32×32 and 4096 bytes. The wire value is a bounded `data:image/png;base64,...` string. There is no network image fetch. SVG and other unsupported resources fall back to the default book icon. Claude's current native `reload_skills` response does not report custom interface appearance; its skills use the default icon and native name. Do not infer Claude metadata from Codex paths or scan unrelated filesystem directories.

Display names are bounded to 200 UTF-8 bytes with no control characters; brand colors are six-digit hex. Message snapshots do not refresh from the current catalog. The Codex send path revalidates catalog entries and stores the verified appearance in the exact-client/native-message receipt. Execution receives only the native `skill` name/path fields. Removed skills remain readable in old messages via the receipt.

Web rendering uses noneditable inline references and maps visible label offsets back to the canonical draft token. Android's local Expo module `salcara-skill-input` adds `ReplacementSpan` objects to the real ReactEditText: the book/PNG and display name are drawn over the `$name` range without inserting invisible or replacement characters. The controlled value and UTF-16 selection remain canonical. The module checks the complete expected text before applying asynchronous decoration and reports decorated content height for Fabric layout. Existing iOS/older-runtime fallback keeps the attributed native TextInput; this change does not provide an iOS inline-image implementation.

Automated JS tests cover custom labels, colors, native canonical offsets, deletion, UTF-16 text, literal lookalikes, exact identity, retries and caches. Go tests cover icon confinement/normalization and native execution/history identity. These tests are not evidence of Android IME/device behavior: validate keyboard composition, range selection, multiline wrapping, font scaling, same-name skill deletion, and source switching on the final Android package.
