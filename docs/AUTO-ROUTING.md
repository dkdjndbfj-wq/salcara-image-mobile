# 自动对话与生图路由

Salcara AI 默认使用一个聊天输入框，不要求用户在“对话”和“图片创作”页面之间来回切换。每次发送时，应用只根据本条提示词和附件判断请求类型：

| 输入 | 默认动作 | 是否调用图片 API |
| --- | --- | --- |
| 上传图片后说“分析、识别、描述、总结” | 对话 / 视觉分析 | 否 |
| 上传 PDF、Word 等文件后要求分析 | 对话 / 文件分析 | 否 |
| 明确说“生成一张海报、绘制图片、做一张封面” | 对话 API 先整理和检查要求，再调用 Images API | 是 |
| 有参考图并说“修改、换背景、按这张图创作” | 对话 API 先整理和检查要求，再调用 Images 编辑 API | 是 |

图片附件本身不会触发生图。识别到图片意图后，自动模式先调用配置好的对话服务商生成内部作图说明；只有这一步成功，才会向独立图片服务商发起一次付费请求。对话步骤失败时不会继续扣图片费用。

## PDF 分析后继续生图

1. 在同一会话上传 PDF，发送“请分析这份方案”。这条消息只调用对话 API。
2. 下一条发送“根据刚才的方案生成一张宣传海报”。应用会从历史消息恢复最近的文件附件，并再次交给对话模型整理为作图说明。
3. 作图说明成功保存后，再调用图片 API。若图片下载失败，重试只下载原 URL，不会重新提交生图。

## 服务商配置

建议至少保存两个服务商：

- 对话服务商：配置 Chat Completions、Responses 或 Claude Messages 模型，用于问答、视觉、文件分析和自动生图前的确认。
- 图片服务商：只配置 Images 模型、画质、比例和清晰度。

服务商可以使用不同地址和密钥。自动模式找不到对话服务商时会停止在图片请求之前并给出配置提示；“仅图片创作”手动模式仍可在没有对话模型时直接调用图片接口，适合确认过兼容性的高级用户。

## 安全原则

- “生成一段文字”“这个模型可以生成什么”不会被当作生图请求。
- 识别、分析、总结等意图优先保持在对话 API。
- 自动模式不做用户看不见的图片重试；已保存的作图说明会用于手动重试，避免重复支付解析费用。
