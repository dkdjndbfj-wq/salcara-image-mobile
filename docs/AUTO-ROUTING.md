# Agent：对话模型自己决定何时画图（v1.4.0 起）

v1.4.0 起不再用关键词正则猜测“这句话是不是要生图”。每条消息都交给对话模型处理，同时把一个 `generate_image` 工具提供给它——与 ChatGPT、Gemini 的做法相同：

| 用户说 | 模型的行为 | 调用图片 API |
| --- | --- | --- |
| “帮我总结这份方案” | 直接回答 | 否 |
| “这张图里是什么花？” | 看图回答 | 否 |
| “画一张露营海报，横版” | 调用 `generate_image`，`aspect_ratio: 16:9` | 是 |
| “把刚才那张改成夜景” | 调用 `generate_image`，`reference_images: ["图3"]` | 是（编辑） |
| “给我写一段生图提示词” | 输出文字 | 否 |

## 图片编号

对话里出现的每张图片（用户上传的、之前生成的）都按顺序编号为 图1、图2……，编号写在发给模型的上下文里。模型在工具参数里写编号，应用在本地把编号解析回文件：用户本轮上传的图片直接使用，之前生成的图片会复制一份规范化的参考图。首张图若有涂抹蒙版，只有当模型选它作主图时才会带上蒙版。

为了控制请求体积，历史中只有最近 3 张图片会重新附带像素；更早的图片仍可按编号引用。

## 协议与兼容

- Chat Completions：`tools` + `tool_choice: auto`，流式解析 `delta.tool_calls`
- Responses：`function` 工具，解析 `function_call` 输出项
- Claude Messages：`tools` + `input_schema`，流式解析 `input_json_delta`
- 中转若以 400/422 拒绝工具定义（此时尚未产生费用），会立即用“文本协议”重试一次：模型在回复末尾输出一行 `<<<IMAGE {...}>>>`，应用解析后从界面中隐藏。同一模型在本次运行内会记住这一点。

## 计费安全

- 模型给出的作图参数在调用图片 API **之前**写入消息；失败后“重新绘制”只重复图片请求，不会再次调用对话 API。
- 图片已生成但下载失败时，只重新下载原 URL。
- 没有配置对话服务时，每条消息直接作为作图描述发给图片 API；此时不能分析文件。
